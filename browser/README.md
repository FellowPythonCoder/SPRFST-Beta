# SPRFST Browser

A web browser whose engine is written in SPRFST.

Not a wrapper around WebKit, not a window with someone else's engine in
it. The address parser, the HTML parser, the style engine, the layout
engine, the blocker, the cache and the reader are all SPRFST source in
`browser/src`. The window is AppKit, and all it does is paint a display
list the engine hands it and send back what you clicked.

```
sprfst run src/main.spf -- example.com          read a page in the terminal
sprfst run src/main.spf -- --reader bbc.co.uk   the Lens: article only
sprfst run src/main.spf -- --serve              the service the window drives
```

## Project organization

Browser-owned files live under this directory: SPRFST engine modules in
`src/`, native macOS chrome in `macos/`, filtering rules in `rules/`,
offline and fixture tests in `tests/`, and code documentation in `docs/`.
The compiler and runtime remain at the repository root because they are the
language that runs the engine; moving them into the browser would make the
project less organized and would break the other SPRFST examples.

The start page repeats this source map and explains the load pipeline in
plain language, so the browser can document itself without a separate web
site or an embedded documentation engine.

## The five things it does that other browsers do not

**The Shield counts out loud.** Blocking is not a silent slider. Every
page says, in the bottom right, what it cost: `6 ms · 4.6 kB · 5 blocked
· 4 hidden · 9 asked for · 513 words`. `sprfst://shield` lists what was
stopped. Requests are checked before they are made, so a blocked advert
is never fetched, never parsed and never laid out — it is not hidden
after the fact.

**The Lens.** One key (⌘K) and any page becomes the article: headline,
words, pictures. It works by scoring every element — words, commas,
how much of it is link text, whether it calls itself an article or a
sidebar — and keeping the winner. No service, no network, no account.

**Ember.** The engine hands over real colours; the painter can re-tint
them to the SPRFST palette (deep black, soft white, amber) without
refetching anything. ⌘U turns it off and the page's own colours come
back. Because the painting is ours, this works on every site, including
the ones that have never heard of dark mode.

**The budget meter.** `fetch · read · style · lay out` are measured
separately for every page and reported by the service, so you can see
where a slow page went wrong. A four kilobyte article is read, styled
and laid out in about six milliseconds.

**Pages of its own.** `sprfst://start`, `sprfst://shield`,
`sprfst://trail`, `sprfst://settings` and `sprfst://about` are real HTML
generated by the engine and laid out by the same pipeline as everything
else. There is no separate "chrome page" renderer, and no web view
hiding anywhere.

And there is no Google in it. Not in the search — DuckDuckGo's plain
HTML endpoint is the default and the setting is one line — not in the
fonts, not in a tracker, not in an SDK.

## The rule format

`rules/shield.rules`, plain text, one rule per line:

```
||ads.example.com^        the host and every host under it
||example.com/ads/        a host together with a path
/pagead/                  anywhere in the address
|http://tracker.          the address starts like this
.gif|                     the address ends like this
@@||example.com^          an exception: never block this
||beacon.io^$third-party  only away from the site you are on
##.ad-banner              hide these elements everywhere
news.example##.promo      hide these elements on one site
~~ a comment
```

Host rules are matched by walking the domain labels, so one line covers
every subdomain. Exceptions are checked first. Edit the file, reopen the
browser; `sprfst://shield` says how many rules were understood.

## What it cannot do

This is the honest list. Nothing here is hidden behind a spinner.

**There is no JavaScript engine.** Scripts are not fetched and not run.
A page that builds itself in the browser arrives empty; a page that is
HTML arrives whole. This is also why it is fast and why nothing can
track you between pages. Writing a JS engine is a larger project than
the browser.

**No TLS of its own.** The SPRFST runtime has no TLS, so `https://` is
handed to `curl`, which every Mac has. `http://` goes over a raw socket
written in SPRFST. A TLS implementation in the runtime is the next real
piece of work.

**Layout is lines and blocks.** Text, headings, lists, quotes, rules,
tables as rows, images as boxes, `pre` as itself. There is no float, no
flexbox, no grid, no absolute positioning: elements that ask for them
are laid out in order instead. Most articles are indistinguishable;
some magazine layouts are plainer than they were meant to be.

**One typeface.** The engine measures in Helvetica and the window paints
in Helvetica, so lines break exactly where the engine said they would.
Web fonts are not fetched, since they could not change the measurement.

**No forms, no video, no audio.** Clicking a link works; submitting a
form does not. `<video>` and `<audio>` are boxes. These are not hard to
add on top of what is there, but they are not there.

**Images are fetched by the window, not the engine.** The engine passes
the address of every picture that survived the Shield; AppKit loads it.
A blocked image is never passed, so blocking is real rather than
cosmetic.

**Selection is by the page, not by the word.** ⇧⌘C copies the whole
page as text; dragging a selection across words is not implemented.

## Building it

```
make                                  the interpreter
cd browser && ../build/bin/sprfst test
./tools/build_browser_app.sh --install    the app, on a Mac
./tools/make_browser_dmg.sh               the disk image
```

On anything that is not a Mac, `--stage` lays the bundle out without
the executable, and `make_browser_dmg.sh` writes the installer image
instead: the whole project plus a double-clickable builder.
